# Feature 024 Update: Admin Route Migration Required

**Date**: 2025-10-30  
**Impact**: Route conflict resolved - admin moves to `/admin`, user dashboard gets `/dashboard`

---

## What Changed

Feature 024 (User Dashboard) was planned to use `/dashboard` as the main authenticated user landing page. However, the existing admin section already uses `/dashboard` routes.

**Resolution**: Migrate admin section from `/dashboard` to `/admin` before implementing Feature 024.

---

## Updated Route Structure

### After Migration

**Admin Routes** (admin-only access):
- `/admin` - Admin home page
- `/admin/users` - User management
- `/admin/performance` - Performance monitoring

**User Routes** (authenticated users):
- `/dashboard` - User dashboard (Feature 024) - NEW
- `/entries` - Entries management (existing)
- Other user-facing pages...

**Public Routes**:
- `/` - Homepage (redirects to `/dashboard` if authenticated)
- `/login`, `/register`, `/about`, etc.

## Questions?

**Q: Why not use `/user-dashboard` or `/home` for Feature 024?**  
A: `/dashboard` is the most intuitive and common convention for the main authenticated user landing page. Moving admin to `/admin` provides better semantic clarity for both areas.

**Q: Can we keep both at `/dashboard` with different middleware?**  
A: No. Next.js file-based routing doesn't support multiple pages at the same route. Admin and user dashboards need distinct routes.

**Q: What if an admin user tries to access the old `/dashboard` URL?**  
A: They'll get a 404. We'll add a communication plan to notify admin users before deployment and provide the new URL.

**Q: Do we need to update the database?**  
A: No. This is purely a frontend routing change. No data model changes required.

**Q: Will this affect the existing `/entries` page?**  
A: No. The entries page is unaffected. Feature 024 adds a new dashboard that complements the existing entries page.
